## Verification scope and deliberate limits

Meaningful narrow families and red/green tests preceded combined verification. The owned full-suite command supplies PostgreSQL prerequisites and runs every solution test; no database test is silently filtered/skipped. The final combined run has 687 passes (Core 339, App 187, Windows 17, Integration 144), zero failures/skips: [log](full-tests-v104-final.log), [TRX](full-test-results-v104-final/). The earlier 670/672-test checkpoints remain historical evidence. Source-string/fake SQL tests are not counted as transaction proof. The [installed inventory correction](inventory-correction.md) and fresh-directory preview cleanup regression resolved additional defects before packaging; their focused red/green evidence and independent approvals are retained.

Pre-publication destination IO failure is injected rather than exhausting the user's disk. Native preview records the verified launcher path instead of certifying Office/CAD/Adobe reopen. Benchmark mode uses explicit legacy metadata without PostgreSQL/VSS/mirrors. These limits match the bounded slice; professional fidelity, scale, service authorisation/vault isolation, configuration/lifecycle, independent disaster recovery and the UI rebuild remain open roadmap packages.

The implementation adds no dormant Options fields or user bypass for mandatory verification. Limits are typed/defaulted internal safety bounds. Folder ordering follows storage timestamp precision; it is a correctness rule, not a user policy setting.
