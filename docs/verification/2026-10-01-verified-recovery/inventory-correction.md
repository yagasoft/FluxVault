# Installed inventory refresh correction

The resumed v1.0.3 desktop session exposed disappearing version rows and selection after the service invalidated its status cache. The database still held all ten versions: a full status read returned ten, an empty-scope backup invalidated the cache, the following fast status returned zero, and another full read returned ten. This is recorded in [live IPC evidence](installed-status-cache-regression.json) and [desktop evidence](installed-ui-inventory-regression.json).

`HasVersionInventory` now distinguishes an authoritative empty inventory from an unavailable snapshot. Fast status remains cache-only. A missing repository root is unavailable and is never recreated by status. Cache identity includes repository path and metadata configuration; generation checks stop reads begun before invalidation from republishing their older snapshots. Version and tracked-entry reads are independently covered by barrier-controlled regressions.

An automatic UI refresh makes at most one additional read-only full request when the fast snapshot is unavailable. If that fails or remains unavailable, versions and selection remain visible with a warning. Shared status application also protects profile command responses: same-profile inventory is retained, while changed profile/storage identity clears previous version and file-browser recovery entries. Mutation commands are never retried. These are internal correctness rules, not configurable user policies.

The correction was developed from failing regressions: [initial UI](inventory-app-red.log), [unavailable full read](inventory-app-unavailable-red.log), [profile response](inventory-profile-red.log), [profile file browser](inventory-profile-browser-red.log), [cache availability](inventory-core-red.log) and [root/generation/identity](inventory-core-review-red.log). Focused verification passed [65 App refresh cases](inventory-app-reviewed.log) and [15 Core status cases](inventory-core-green.log). Private IPC integration cases also assert the wire contract for cold, warm and invalidated status. Broader candidate and installed desktop results are recorded in the [main evidence](README.md).
