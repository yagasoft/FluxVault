## Rehearsal sequence

1. Record installed service identities/process start times and hashes of installed HBA/ident/FluxVault configuration. Keep their contents out of evidence. Recheck resource absence and ownership prerequisites.
2. Create the fixture actors, group and GUID root. Protect PostgreSQL/catalogue/content areas for the fixture host and trusted administrators. Give users only the probe/runtime access and their own generated output areas needed by each test. Do not relax existing installation ACLs or machine logon policy.
3. Start only the generated cluster with a verified owned postmaster. Use authenticated SCRAM bootstrap with a one-time high-entropy generated administrator password, never a network `trust` window. The temporary initdb password file must be protected for the runner/administrators/SYSTEM and removed as soon as initdb finishes; pass the password to the child connection environment without command-line/log exposure, clear it afterwards and dispose its owned processes. Provision the database/service role, then disable bootstrap-role login, set its password to NULL and remove its network admission immediately. The resulting HBA permits explicit SSPI only for the fixture database/role on both loopbacks and rejects other connections. No normal HBA edit/reload/restart occurs. Temporary bootstrap secrets are not saved in the ownership manifest, evidence or reusable configuration.
4. Initially leave the SSPI map empty so authentication cannot admit anyone. Run the owned LocalSystem probe without a database password, verify its actual Windows SID is `S-1-5-18`, and correlate the failed connection with PostgreSQL's qualified authenticated principal. If that principal cannot be established reliably, stop without adding a permissive map.
5. Add only that exact observed principal-to-role mapping, retaining the realm and using literal safely quoted tokens. Reload only the owned cluster, without restarting it. Verify password-free LocalSystem connection through Npgsql and libpq, plus real A/B denial on IPv4 and IPv6, including attempted service-role/identity impersonation. An SSPI handshake failure is a blocked prerequisite, not evidence that the intended mapping works. Never substitute `trust`, strip the realm or write reusable credentials to get a pass.
6. Exercise actual source/output/storage ACLs, authenticated pipe identities and token lifetime with A/B. Once S1 is implemented, use these actors for creator ownership, explicit user/group grants, restart persistence and same-database two-vault capture/restore. Later packaged, remote-client, final-path race, logged-off/reboot and complete command cases retain their original gates; this prerequisite rehearsal does not complete them.

PostgreSQL recommends retaining the realm with an explicit user map. Its implementation logs the authenticated principal for an unsuccessful map, allowing an owned failed probe to establish the concrete value before admission. These are capabilities to rehearse, not evidence of successful LocalSystem integration here. [PostgreSQL SSPI](https://www.postgresql.org/docs/18/sspi-auth.html), [mapping implementation](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/libpq/hba.c).

## Cleanup and refusal rules

Every execution uses `finally` cleanup, including partial provisioning and failed tests. Before/after each creation, persist a credential-free ownership journal protected for the runner/administrators/SYSTEM, containing the intended and returned resource identities. Provide repeatable recovery teardown from this journal for a killed runner or machine interruption. Refuse another run while an unresolved journal/resource remains; do not automatically adopt or delete conflicting resources. Do not rely on `finally` alone.

Stop and join only owned A/B clients/host/probes, stop/unregister only the owned task, then stop only the postmaster matching the generated data directory, binary, PID and start time. Task timeouts include surviving children and launcher failure before PID discovery; inspect the protected ownership evidence and process markers, not just the scheduler's task state. Verify each process has exited; a PID reused by another process must never be killed.

Remove fixture group membership, any Windows user profiles created for the recorded fixture SIDs, the exact group and accounts only if their SIDs still match, and the exact GUID directory only after resolving it beneath the approved parent and proving its processes have exited. Teardown inspects directory entries without following reparse points, including links planted in user-writable output; remove only the link itself or refuse, never recursively delete its target. Preserve redacted logs/results and the completed ownership journal in this worktree before deletion. Account/task collision or changed ownership causes refusal, retaining evidence and a specific cleanup report. Do not mark cleanup successful if any owned resource remains.

Recheck installed HBA/ident/configuration hashes and original service process identities. There is no deployment, migration, installed database write, production access or service/PostgreSQL restart in this authorisation. If a machine prerequisite is missing, report it and stop that fixture path rather than changing unrelated settings.
