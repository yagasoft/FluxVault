# Caller-authorised diagnostics export

This bounded NEXT-002/S2 batch enables diagnostics export through the existing single-vault Windows service. It adds no database schema, policy setting, vault lifecycle or cloud dependency. The existing creator/grant policy requires history-read authority. Repository binding, admitted configuration revision and operation receipts remain authoritative.

Catalogue admission validates an unambiguous absolute local directory without inspecting or creating filesystem objects. The shared syntax check is extracted from native caller file access; it now rejects repeated separators before Windows can normalise them. The executor derives a new filename from the admitted operation ID and uses the existing caller-created, pinned output target through publication. Existing entries cannot be overwritten. Core streams a versioned document containing identity, revision and authorised status, including the current automatic-protection restriction. It owns/disposes the target from entry, including status-generation, serialization/write and cancellation failures. Published files and publication warnings are preserved.

The view-model uses a cancellable folder picker, captures identity/revision/operation before dispatch, validates both returned output paths and the bound acknowledgement, retains warnings and blocks concurrent exports. Export neither saves pending protection edits nor starts backup. Lost, cancelled or malformed acknowledgements explain that output may already exist and display the original operation ID; they never claim success or automatically retry. Exact replay and receipt lookup return the recorded result, even after the caller edits or deletes the report.
