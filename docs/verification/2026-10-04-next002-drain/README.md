# Authorised mirror drain

This bounded NEXT-002/S2 batch implements mirror drain through the single-vault Windows executor. It adds no vault lifecycle, schema migration or new policy setting. The existing creator/grant policy, repository binding, protected storage, SSPI connection and shared mutation gate remain in use. Drain requires maintenance and history-deletion authority and at least two enabled configured destinations before admission.

Repository execution moves/deletes verified mirror artefacts and retains its health report without saving configuration. Catalogue completion checks the original request fingerprint and exact admitted receipt, then compares the admitted configuration revision. A successful, healthy, applied drain with no remaining actions disables only its requested destination and increments the configuration revision. Configuration, completed receipt revision and response commit in one database transaction. Incomplete/failed results keep the destination enabled and retain their original revision. A newer configuration, cancelled completion or unconfirmed commit leaves an uncertain outcome; the admitted repository effect is never automatically executed again. Exact replay is evaluated before checking the current destination enablement.

The view-model validates the bound destination, operation and acknowledged revision, including malformed/null report collections. It captures its accepted configuration before dispatch and applies the confirmed disablement only to the same accepted identity/revision/configuration. Protection selections and other pending edits remain in place. A response received after a newer accepted configuration cannot regress it. Incomplete drain explains that the destination remains enabled.
