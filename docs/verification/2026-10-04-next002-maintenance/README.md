# Authorised repository maintenance

This bounded S2 batch exposes repository health, retention preview/run, scrub, restore rehearsal, mirror repair preview/run, mirror placement preview/run and drain preview through the protected single-vault Windows executor. It uses the existing creator/grant permissions, installed repository binding, guarded storage, SSPI metadata connection, shared operation gate and durable mutation receipts. It adds no vault lifecycle or new policy settings.

Mirror selection is checked against the authorised configuration before new receipt admission. Repair can explicitly target all mirrors by omitting its selector; a supplied blank, unknown or disabled selector is refused. Drain preview requires an enabled configured destination. Matching remains case-insensitive, and retained receipt replay is checked before current-selection validation. Refusal explains the selection problem without exposing configuration. A completed maintenance report must still be assessed using its health and issue fields.

The health store publishes a flushed temporary file using replacement for an existing snapshot. An open reader can finish reading the original report while a subsequent read receives its replacement. Cancellation is checked before publication, and failed or cancelled saves clean only their own temporary file. The controlled Windows reader regression rejected the first `File.Move` attempt; `File.Replace` passed it. This uses the Windows [replacement API](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files).

Retention invalidates cached inventory before execution and in `finally`. A status read during a partially failed or cancelled deletion cannot leave the old history cached after completion. This does not imply that partially applied retention rolls back.
