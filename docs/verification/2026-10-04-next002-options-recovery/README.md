# Options save recovery after restart

This bounded S2 batch extends the existing per-user configuration-save ledger to Options. The complete submitted configuration and original repository/operation/revision are frozen, validated, reserved under the shared file gate and flushed before dispatch. The existing `pending-protection-save.json` and `.lock` filenames are retained. The optional origin defaults to Protect for existing records; unknown origins and Options records carrying purge intent or either purge scope list are refused. Origin stays in the client ledger and never changes server authorisation.

Reopening Options restores its submitted editable settings only after verified repository binding. Its accepted baseline remains the actual service configuration. Receipt checking requires the original successful operation at its original revision plus one, then fresh bound current status. Missing, denied, unavailable and mismatched receipts retain the pending snapshot and edits. Historical/current-setting differences keep a review gate. Explicit **Reload saved options** revalidates the captured record and current settings, refuses changed records or newer in-flight edits, and conditionally clears before applying settings. No check or reload starts a backup.

The main window shares the same ledger. Pending Options recovery can open while protection drafts exist, and dependent save/backup remain blocked. Closing Options preserves protection drafts. If saved settings changed, those drafts remain blocked for explicit review/reload rather than silently rebasing them. Options never adopts or clears a Protect-origin record. Corrupt, busy and foreign records are kept and block dispatch. Save, receipt and reload commands remain owned by the Options window until they finish.
