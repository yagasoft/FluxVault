# Atomic protection toggle and authorised sync status

This bounded S2 batch enables the existing single-vault `SetProtectionPaused` toggle and `GetSyncStatus` service commands. It does not complete NEXT-002, NEXT-004, background/VSS capture, the UI rebuild or normal installation rollout. The agreed architecture, creator ownership/access policy, roadmap and applicable gates remain unchanged.

The toggle requires protection-management authority and changes only the authoritative `IsEnabled` setting. Configuration, incremented revision and completed receipt commit in one PostgreSQL transaction. Exact replay precedes stale-revision checks and never toggles again. Unrelated configuration, access and purge payloads are refused before new receipt admission. The Windows executor recognises the command but refuses direct execution; the handler returns the completed catalogue receipt. Post-commit payload/acknowledgement failures remain uncertain and preserve the original operation identity.

Toggle, save and backup share the existing mutation gate. A queued backup is admitted only after the toggle acknowledgement completes and receives the new authoritative snapshot/revision. Disabled full and targeted backup return before source inspection, request/source enumeration, capture, deletion reconciliation or retention. Protected binding/storage checks remain mandatory. `GetSyncStatus` requires history-read permission, returns the existing full status/sync snapshot and admits no mutation or receipt. It starts no sync, cloud or background work.

Status and diagnostics distinguish paused manual backup from unavailable automatic protection. The activity pane's automatic-protection control stays disabled. Explicit pause/resume UI remains in NEXT-004; any future MainWindow activation must recognise the toggle's incremented revision in acknowledgement validation. Existing full-record saves and actual view-model draft/failure/dependent-backup regressions remain included and unchanged.
