# Caller-authorised file previews

This bounded S2 batch enables the single-vault product preview command. Recovery authority, repository identity, revision and durable operation receipts remain required. The privileged executor publishes fully verified file bytes through a pinned caller-authorised target. Folder previews are refused before output preparation. A fresh destination is mandatory, including during native publication; existing destinations are preserved. Preview never writes restore-lineage hints.

The dashboard allocates a fresh path in a private Windows-user cache, verifies the acknowledged destination/result, sets read-only attributes through a verified handle and launches the viewer in user context. A verified copy remains available if viewer launch fails or is cancelled, with publication warnings retained. The service has no shared preview cache. The cache refuses shared/inherited roots, reparse components and hard-linked files without adoption, and cleans only expired flat entries through verified handles, inspecting at most 1,024 entries per request. Open/refused entries remain for a later attempt.

The typed `VersionPreviewPolicy.RetentionDays` defaults to 2, normalises non-positive values to 2 and caps at 365. Options loads and saves it through the actual stores, and expiry has a tested runtime effect. The default cache uses the user's temporary path and SID. A real default-path check found a redirected ancestor of Local AppData on this PC; the existing reparse refusal was preserved and the temporary-path default passed. The existing directory was not adopted or removed.
