# Committed protection save and selective history purge

This bounded S2 batch enables the existing combined save/purge command through the single-vault authorised service. It retains the original full-record configuration save, explicit purge confirmation, permission checks, repository binding, mutation gate and durable receipt contract. It adds no vault lifecycle or future multi-vault abstraction.

The catalogue validates explicit, nonempty removed scopes and an explicit preservation list before saving. Paths must be absolute and scope kinds defined; null scopes are refused. Configuration CAS advances its revision once and admits the operation. The executor checks the admitted receipt, actor, required permissions and committed revision, then applies the durable configuration without another save. Guarded storage failure reports a successful configuration save with a failed purge. Cancellation or failed receipt completion remains an unknown outcome; a duplicate admitted request cannot automatically repeat destructive work.

Purge computes the complete lineage and folder-reference closure, then refuses any intersection with preserved history before metadata, primary or mirror deletion. This corrects a reproduced defect in which reference expansion could add preserved versions back to the deletion set. Refusal leaves history recoverable. Other purge failures can occur after partial deletion and must not imply rollback. The existing actual Protect flow retains its durable review gate, explains the failure and blocks dependent backup. Status inventory is invalidated after purge finishes, including failure or cancellation, so a concurrent read cannot leave deleted history cached.
