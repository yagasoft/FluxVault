# Protection save recovery after restart

This bounded S2 batch preserves a dispatched protection save across dashboard restart. Before IPC, the complete configuration, repository/operation/revision and purge intent/scopes are frozen, validated against the finite request size/depth, written under an exclusive cross-session file gate and flushed. The persisted and sent snapshots are identical. Another session cannot overwrite a pending save or clear a different complete snapshot. Corrupt, duplicate, unknown, oversize, busy and wrong-binding state is preserved and blocks dependent work.

Reopening restores editable protection fields only after verified repository binding; the accepted baseline remains the current service configuration. Refresh cannot resolve the persistent uncertainty from a matching configuration fingerprint. The visible WPF **Check save outcome** action queries the original receipt and requires a successful result at its original revision plus one. It then verifies fresh current settings. Unavailable/denied/unknown/mismatched receipts remain pending; no check dispatches a backup. A historical result cannot roll back a newer accepted baseline.

Only definite pre-effect rejection codes clear an immediate rejected save's operation record. Generic unsuccessful replies and transport exceptions remain uncertain. A saved-but-failed purge, different newer settings or unavailable current settings retain a durable review gate. Explicit Discard reloads verified current settings only after review, revalidates the exact reviewed record after its status request and conditionally clears that captured snapshot. A newly published record is never cleared by discard. Failed reads revoke review permission. Controlled discard omits optional telemetry so a later failure cannot reverse its result or overwrite newer edits.

## Evidence

- [Store red](store-red/App.trx): 6 actual file-store failures before implementation; [store green](store-green/App.trx): all 6 passed. Additional bounds/nested/case-variant regressions are included in the final suite.
- [Flow red](flow-red/App.trx): 3 actual dashboard/production-store cases failed before wiring. [Flow green](flow-green/App.trx): all 3 passed. The final versions exercise acknowledgement loss after the real store commits, reopening, identical durable payload at dispatch, exact original receipt and no dependent backup.
- [Focused verification](focused/App.trx) passed 97 cases, including retained full-setting preservation, cancelled/failed saves, newer edits, original revision checks, failed purge and historical-save review.
- Independent review found an unreviewed cross-session record could be cleared by discard, and case-insensitive binding could accept a case-variant nested field. All three [review regressions failed](review-red/App.trx) before correction, then [passed](review-green/App.trx). A further final case proves previously confirmed review is revoked when the file becomes unreadable.
- A further review found optional telemetry could fail after discard had applied settings. The actual VM/real-store/WPF STA [Performance-workspace case failed](performance-red/App.trx), then passed after that optional request was omitted from controlled discard.
- The [final App suite](app-final-3/App.trx) passed **296/296**, with no skips. It includes visible WPF action binding, unavailable current status, corrupt/busy records, pending edits and every review regression. The [Release solution build](build-release-final.log) passed with **zero warnings/errors**. [Process census](process-census.json) verifies no launched build/test processes remain.

An older preservation assertion compared nested list references; freezing necessarily creates new lists. It now compares their complete serialised values. The old refresh-only retry case now additionally requires the original receipt before a backup, strengthening the interruption contract. Earlier failing whole-suite results remain retained and are not passing evidence.

Independent Astra review approved the final bounded implementation after all corrections. These tests require no normal service or PostgreSQL changes. Options restart persistence, never-dispatched edits, broader command/background semantics, full accessibility/performance and final G01/rollout remain open.
