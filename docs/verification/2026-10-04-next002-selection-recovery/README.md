# Caller-authorised selection recovery

This bounded S2 batch implements selection preview and latest file/folder recovery through the existing single-vault catalogue and Windows executor. It does not complete NEXT-002, the UI rebuild or the normal installation rollout. The roadmap, creator ownership/access policy and applicable security, recovery, cleanup and performance gates remain unchanged.

Preview requires recovery permission but admits no mutation or receipt and creates no output. The catalogue validates unambiguous local source/destination syntax after authorisation, replay and revision checks, before a new admission. Original recovery is restricted to the selected source. Caller-native output inspection retains blind-traverse ancestors and verifies the immediate parent/leaf; only a missing component below a verified chain proves absence. Unavailable access, volume-anchor failures, reparses and verification errors remain failures. Execution checks the destination again through the existing pinned target. A new-file request cannot authorise a late overwrite; folders require a new destination and cannot merge existing entries.

Exact folder history remains preferred. Older independent-file history becomes one forest plan under one repository lease with shared node, depth, expanded-entry, chunk-reference and metadata budgets, including synthetic directories. Unsafe/colliding names and file/directory prefixes fail before staging. Latest file history is grouped before deleted entries are excluded; explicit deleted-file recovery retains its validated last-good target. The whole folder publishes once after every byte is verified. Failed publication creates no lineage hints; post-publication warnings retain verified output.

The actual view-model captures identity/revision/operation, blocks concurrent selection recovery, retains pending protection edits and requires matching summary/output/verification before claiming success. Lost, cancelled or malformed results display the original operation ID and remain uncertain; they neither save settings nor start backup. A failed status refresh retains the verified recovery result and publication warnings. A selected file must return one verified file, including a legitimately empty file.
