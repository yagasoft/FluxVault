# Remaining gates in the authorised manual slice

The existing independent Astra reviewer assessed the remaining plan against
the current single-vault composition. This is a bounded gap assessment, not
final G01 approval or a roadmap revision.

- S01: execute the prepared native packaged A/B test only after its separate
  account-profile/public-certificate-trust approval. Package preparation and
  ordinary native identities cannot substitute for this result.
- S04: prove caller-denied/locked source failure without privileged fallback,
  and no background capture when the existing installation opens without an
  owner session. The current service composes no scheduler or VSS path; keep
  these unavailable and truthfully explained rather than adding those features
  to this manual workflow. Existing path/ACL/race gates remain.
- S07: one controlled owned process termination after durable admission and
  an observable effect, before receipt completion; reopen and verify truthful
  original-ID reconciliation without automatic duplicate execution. Reuse
  applicable WAL, acknowledgement-loss and client-ledger evidence; a crash
  matrix for every command is unnecessary.
- D01/S3: verify the actual implemented save, backup, paged history and recovery
  workflow, including failure/unknown states, keyboard, Narrator, DPI, high
  contrast and representative larger inventory responsiveness. STA rendering
  alone does not complete these checks. Measure supported workflows before
  deciding whether client accumulation needs another implementation change.
- Rollout preparation: provide explicit once-only fresh protected provisioning,
  an authenticated creator bootstrap, exact SSPI/HBA changes preserving unrelated
  lines/data, retained v1.0.4 rollback assets and live probes. Never adopt staging
  backups or run old binaries against fresh v4 metadata. Normal rollout needs
  independent review and separate operational approval; no PostgreSQL restart.
- G01: independently review the complete final branch and evidence mapping,
  run affected combined checks with zero new warnings, resolve blockers and
  obtain fresh final cleanup/closeout evidence. Milestone acceptance does not
  substitute for final review.

The reviewer identified no additional S06 implementation blocker: existing
framing, admission, deadline, output, token, cancellation and joined-shutdown
tests address the specified transport boundary. Final review must verify their
composition. No generic fairness/stress programme is added.

Unsupported conflict resolution, never-dispatched Options draft retention,
owner-session background delivery, a general lifecycle supervisor and an
independent disaster-recovery programme retain their roadmap positions. They
do not broaden this slice, and unavailable paths must stay unavailable.
